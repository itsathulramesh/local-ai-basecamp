Hugging Face: finding and judging models

Hugging Face is the main place where open models live, a mix of GitHub and an app store for models. Knowing how to read a page there lets you move beyond whatever a tool suggests.

What you will learn

  • Search for models and read a model card
  • Judge whether a repository is trustworthy
  • Pick the right file for your hardware
  • Use the model's recommended settings

Anatomy of a model page

  • Name and publisher: publisher/model-name. The publisher matters for trust.
  • Model card (the README): what it is, training notes, licence, recommended settings, limitations.
  • Files and versions: the actual files and their sizes.
  • Community: discussions, where people report bugs, problems and benchmarks.
  • Tags and counts: parameter size, downloads and likes.

Who made this version?

Models come in layers of re-uploads:

  1. The original from the lab, such as Qwen, Google or Meta, in safetensors.
  2. GGUF conversions, made by community members who specialise in quantizing (several well-known names do this for nearly every release), or by the lab itself.
  3. Fine-tunes and merges, where someone trained further or blended models. This includes "uncensored" or "abliterated" versions (module 5).

The model card of a derivative should name its base model. If it does not, treat it with caution.

Trust checklist

Choosing the file

For a GGUF repository, choose a quantization from the list so that file size plus 1.5 to 3 GB for cache and overhead fits your VRAM. As a quick check: VRAM minus about 2.5 GB is the largest file you should consider for decent context. LM Studio's Discover tab does this for you with a "will it fit" badge.

Read the recommended settings

Look for a "Best practices" or "Usage" section. Authors often specify temperature, top-p, and whether to enable thinking. Following them avoids a lot of "why is this model terrible" confusion.

Gated models and tokens

Some models require you to accept a licence on the page before downloading. You do this with a free Hugging Face account. If you use scripts, you create an access token in your account settings. Treat tokens like passwords: never paste them in public places.

Downloading from a script

pip install -U "huggingface_hub[cli]"
hf download publisher/model-name-GGUF model-name-Q4_K_M.gguf --local-dir .\models

The tool was renamed from huggingface-cli to hf in newer versions. Run hf --help if the command is not found.

Check yourself

A repository has no model card, no stated base model and 12 downloads. What should you do?

  1. Be cautious and prefer a better-documented alternative
  2. Download it because the file is small
  3. Run the installer that comes with it

Missing provenance is a red flag. There are nearly always well-documented versions of any popular model.

You have 12 GB of VRAM. Roughly what is the biggest GGUF file to consider?

  1. 12 GB
  2. 20 GB
  3. About 9 to 9.5 GB

Leave 2.5 to 3 GB for cache and overhead.
