Windows toolbox: terminal, Python, Git and optional WSL2

You said you know basic Python and some terminal. This lesson tightens that up into a working setup on Windows, so later lessons can say "run this command" without surprises.

What you will learn

  • Use Windows Terminal and PowerShell for the commands in this course
  • Install Python and Git with winget
  • Create and use a virtual environment
  • Set up one AI Python environment with PyTorch and Transformers for the whole course
  • Know what WSL2 is and when you will want it

Terminal basics

Install Windows Terminal from the Microsoft Store if it is not already there (Windows 11 includes it). It hosts PowerShell tabs. Commands in this course are written for PowerShell. A handful you will use constantly:

cd $HOME\ai-lab        # change folder
ls                     # list files (alias for Get-ChildItem)
mkdir experiments      # make a folder
code .                 # open the folder in VS Code, if installed
cls                    # clear the screen

Install Python and Git

winget is Windows' built-in package manager.

winget install Python.Python.3.12
winget install Git.Git
winget install Microsoft.VisualStudioCode

Close and reopen the terminal, then check:

python --version
git --version
If python opens the Microsoft Store

Windows has "app execution aliases" that can hijack the command. Open Settings, search "Manage app execution aliases" and turn off the Python entries, or use py (the Python launcher) instead of python.

Virtual environments

A virtual environment is a private folder of Python packages for one project. AI libraries are large and have strict version needs, so keeping each project separate prevents breakage.

cd $HOME\ai-lab
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install --upgrade pip
pip install openai requests

Your prompt shows (.venv) when it is active. Run deactivate to leave it.

If activation is blocked

PowerShell may say scripts are disabled. Allow scripts you wrote or downloaded for your own account only:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

A Python refresher you will actually use

You will not need advanced Python for most of this course. This small script is the pattern behind lesson 6.2. Make sure every line makes sense:

import requests

url = "http://localhost:1234/v1/chat/completions"
payload = {
    "model": "your-model-name",
    "messages": [{"role": "user", "content": "Say hello in five words."}],
    "temperature": 0.7,
}
reply = requests.post(url, json=payload, timeout=120)
print(reply.json()["choices"][0]["message"]["content"])

That is a dictionary, a list of dictionaries, an HTTP request and an index into the JSON response. If any part is unfamiliar, spend an hour on a beginner Python course first. It will pay off many times over.

Your AI Python environment (set up once)

Several later lessons run small models directly in Python: looking at a real tokenizer (1.4), counting parameters (7.2), watching generation (7.4), and steering and editing weights (module 10). They all use one environment with PyTorch (the engine that runs models on your GPU) and Hugging Face Transformers (the library that downloads and loads models). Set it up now, while you are in the terminal, so it is ready when you need it.

  1. Go to pytorch.org/get-started/locally and choose Stable, Windows, Pip, Python, CUDA. Copy the command it shows.
  2. Run these, pasting the PyTorch command where shown:
cd $HOME\ai-lab
python -m venv .venv-ai
.venv-ai\Scripts\Activate.ps1
python -m pip install --upgrade pip
# paste the PyTorch command from pytorch.org here, for example:
# pip install torch --index-url https://download.pytorch.org/whl/cu128
pip install transformers accelerate safetensors openai numpy pydantic

Then check that PyTorch sees your GPU:

python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"

If it prints True and your card's name, you are done. If it prints False, you probably installed the CPU-only build: run pip uninstall torch and paste the CUDA command again. RTX 50-series cards need a build made with CUDA 12.8 or newer. GTX 16-series and RTX 20-series cards work fine; the scripts in this course automatically use float16 on them because they lack bfloat16 support.

Two environments, two jobs

.venv (above) is a light environment for calling LM Studio or Ollama. .venv-ai is the heavier one for running models in Python. Training with Unsloth gets its own Linux environment in lesson 9.3.

WSL2: Linux inside Windows (optional for now)

WSL2 runs a real Linux system inside Windows, and it can use your NVIDIA GPU. You do not need it to run models with LM Studio or Ollama. You will want it later, because some training tools, including parts of the fine-tuning ecosystem, are developed for Linux first and are often smoother there. When you are ready:

wsl --install

This installs Ubuntu. After a restart you get a Linux terminal where Linux commands from tutorials work as written. Module 9 uses it for training. Keep project files inside the Linux filesystem (your Linux home folder), not under /mnt/c, for much better speed.

Check yourself

Why use a virtual environment?

  1. Each project gets its own packages, so versions do not clash
  2. It makes Python run on the GPU
  3. It is required to open the terminal

AI libraries are large and version-sensitive. Separate environments keep projects from breaking each other.

When do you first really need WSL2?

  1. To run LM Studio
  2. To install the NVIDIA driver
  3. When a training tool is easier to run on Linux

Inference apps run natively on Windows. WSL2 is a convenience for Linux-first training tools.
