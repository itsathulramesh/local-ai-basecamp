Fine-tune your own modelLesson 9.615 min

Export: merge, convert to GGUF, run in LM Studio and Ollama

Your adapter is trained. LM Studio and Ollama run GGUF files. This lesson covers the quick export Unsloth already did for you, the manual route with llama.cpp when you need control, keeping the chat template intact, and a checklist before you replace your daily model.

What you will learn

  • Choose between a merged model and a separate adapter
  • Merge, convert and quantize manually with PEFT and llama.cpp
  • Import into LM Studio and Ollama
  • Verify the chat template and run a sanity checklist

The map

RouteStepsUse when
1. Unsloth one-linersave_pretrained_gguf(..., "q4_k_m") in your training scriptMost of the time
2. Manual mergePEFT merge → convert_hf_to_gguf.py → llama-quantizeYou want an importance matrix, a different quantization, or the one-liner failed
3. Separate adapterconvert_lora_to_gguf.py → Ollama ADAPTER or llama-server --loraYou want to switch adapters on and off, or apply one to a close derivative model
Concept: merging

Computing W' = W + (alpha/r) · B·A for every adapted matrix and saving the result as ordinary weights. The merged model is the same size and speed as the base. Always merge into a 16-bit base and quantize once afterwards. Merging into an already-quantized base rounds your small changes on top of the existing rounding error.

Route 1: copy the Unsloth GGUF out of WSL

ls -lh ~/ai-lab/finetune/my-first-lora-gguf/
mkdir -p /mnt/c/Users/$USER_WINDOWS/ai-lab/models
cp ~/ai-lab/finetune/my-first-lora-gguf/*Q4_K_M*.gguf /mnt/c/Users/$USER_WINDOWS/ai-lab/models/

Route 2: the manual path

Merge with PEFT

"""merge_lora.py: merge a LoRA adapter into its 16-bit base."""
import sys, torch
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

BASE, ADAPTER, OUT = "unsloth/Qwen3.5-2B", "my-first-lora", "my-first-merged"
base = AutoModelForCausalLM.from_pretrained(BASE, dtype=torch.bfloat16)
model = PeftModel.from_pretrained(base, ADAPTER)
n = sum(1 for name, _ in model.named_modules() if name.endswith("lora_A"))
if n == 0:
    sys.exit("No LoRA layers injected: module names did not match. Merge where you trained.")
print("LoRA layers injected:", n)
model.merge_and_unload().save_pretrained(OUT)
AutoTokenizer.from_pretrained(BASE).save_pretrained(OUT)   # keeps the chat template
The injected-layer check matters

If the model class differs from the one used in training (for example a text-only class versus a multimodal one), PEFT may silently attach nothing and you would ship the unmodified base. Merge in the same environment that trained the adapter, or use Unsloth's save_pretrained_merged(OUT, tokenizer, save_method="merged_16bit").

Build llama.cpp (once, inside WSL2)

cd ~/ai-lab && git clone https://github.com/ggml-org/llama.cpp && cd llama.cpp
cmake -B build                 # CPU build is enough for converting and quantizing
cmake --build build --config Release -j
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && pip install -U transformers

Newer models need a newer Transformers than llama.cpp's pinned requirements, hence the last install. Prebuilt Windows binaries (including CUDA builds) are also published on the llama.cpp GitHub releases page if you prefer running tools natively.

Convert and quantize

python convert_hf_to_gguf.py ~/ai-lab/finetune/my-first-merged --outtype bf16 \
  --outfile ~/ai-lab/finetune/mine-BF16.gguf
./build/bin/llama-quantize ~/ai-lab/finetune/mine-BF16.gguf ~/ai-lab/finetune/mine-Q4_K_M.gguf Q4_K_M

Always quantize from the 16-bit file, never from another quantized file. If the converter says the architecture is unknown, your llama.cpp checkout is too old: git pull and rebuild.

Optional: an importance matrix

An imatrix records which weights matter most on sample text so 4-bit quantization spends its precision wisely. For a fine-tune, use text that looks like its job (your training conversations plus some general text):

./build/bin/llama-imatrix -m ~/ai-lab/finetune/mine-BF16.gguf -f calibration.txt -o imatrix.gguf -ngl 99
./build/bin/llama-quantize --imatrix imatrix.gguf ~/ai-lab/finetune/mine-BF16.gguf mine-Q4_K_M.gguf Q4_K_M

-ngl 99 needs a CUDA build (cmake -B build -DGGML_CUDA=ON, with the CUDA toolkit installed in WSL). On a CPU build, drop it and be patient.

Route 3: keep the adapter separate

python convert_lora_to_gguf.py ~/ai-lab/finetune/my-first-lora \
  --base-model-id unsloth/Qwen3.5-2B --outtype f16 --outfile ~/ai-lab/finetune/mine-lora-F16.gguf

Then use it with Ollama's ADAPTER (lesson 8.2), or with llama.cpp's server, where you can also scale it:

./build/bin/llama-server -m base-Q8_0.gguf --lora-scaled mine-lora-F16.gguf:0.7 --host 127.0.0.1 --port 8081

Import and run

# LM Studio
lms import $HOME\ai-lab\models\mine-Q4_K_M.gguf --copy --user-repo me/mine
lms ls
# Ollama: Modelfile with  FROM ./mine-Q4_K_M.gguf
ollama create mine -f Modelfile

If the base model supported images, copy its mmproj file into the same LM Studio model folder. Your LoRA did not touch the vision encoder, so the base model's file still works.

Check the chat template inside the GGUF

"""show_template.py: print the chat template stored in a GGUF."""
import sys
from gguf import GGUFReader      # pip install gguf
field = GGUFReader(sys.argv[1]).fields.get("tokenizer.chat_template")
print(field.contents()[:1500] if field else "No chat template: the runtime will guess.")

Then watch what LM Studio actually sends: run lms log stream and send a message. The formatted prompt should match the template you trained with (lesson 7.3).

Ship-readiness checklist

Check yourself

Why merge into a 16-bit base and quantize afterwards?

  1. It is faster to download
  2. Quantized bases cannot be loaded
  3. Merging into quantized weights re-rounds the small LoRA changes and can wash them out

Merge once in high precision, then quantize once.

The merge script prints "LoRA layers injected: 0". What happened?

  1. Training failed
  2. Module names did not match, so nothing was applied
  3. The adapter is too small

Without this check you would ship the unchanged base model.
