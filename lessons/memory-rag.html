Memory and RAG: give your model your documents

A model only knows what was in its training data and what is in its context window. "Memory" and RAG are ways of choosing which extra text to put in front of it. This lesson explains the memory ladder, then builds a working RAG system over your own notes in two short scripts.

What you will learn

  • See the four levels of "memory" as one ladder
  • Explain embeddings, chunking and similarity search
  • Build a working RAG pipeline with LM Studio's embeddings endpoint
  • Know the rules that silently break RAG, and how to check retrieval quality

The memory ladder

  1. Context window (short-term memory). Everything in the current conversation (lesson 1.4).
  2. Saved notes. A file of facts about you or your project pasted into every conversation. ChatGPT's "memory" feature works much like this. In LM Studio it is a saved system prompt or preset. In Ollama it is the SYSTEM of a Modelfile (lesson 8.2).
  3. RAG. Retrieval-Augmented Generation: search your documents for the few passages relevant to the question and paste only those.
  4. Agent memory. A program that writes summaries of past conversations into a store and retrieves them later. It is RAG applied to your own history.
Concept: every kind of memory is "put text into the context"

The model itself never remembers. Each memory system decides which text to put in front of it this time. That is also why RAG beats fine-tuning for facts (lesson 8.1): the facts are read, not recalled.

Embeddings

An embedding model turns a piece of text into a list of numbers (a vector, often 768 or 1,024 long) that captures its meaning. Texts with similar meaning get vectors that point in similar directions, even with no words in common: "How do I reset my router?" lands near "Steps to restart your home Wi-Fi box".

Similarity is measured with cosine similarity: the cosine of the angle between two vectors. 1 means same direction, 0 means unrelated.

Three rules that break RAG silently
  1. Use the same embedding model for documents and questions.
  2. If you change the embedding model, re-embed everything.
  3. Use the prefixes or instructions the model card asks for. Nothing errors if you forget; results just get worse.

Chunking

You do not embed whole documents. You cut them into chunks of a few hundred tokens, each about one thing. For Markdown notes, split at headings and pack paragraphs up to about 1,500 characters. Two refinements matter a lot: overlap (repeat the end of one chunk at the start of the next, so facts on the boundary are not lost) and context headers (prefix each chunk with its file name and heading, so a chunk like "set it to 30 days" still makes sense alone).

The pipeline

  1. Ingest: chunk your files, embed each chunk, save vectors and text.
  2. Ask: embed the question, find the most similar chunks, put them in the prompt with numbered sources, and ask the model to answer only from them and cite.

Setup

In LM Studio, download nomic embed text v1.5 (search "nomic embed") and a chat model. Load both and start the server. Check the embedding model's exact id with curl http://localhost:1234/v1/models. It usually looks like text-embedding-nomic-embed-text-v1.5.

ingest.py

"""ingest.py: chunk your notes, embed them with LM Studio, save to index.npz."""
import json, pathlib, re
import numpy as np
from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")
EMBED = "text-embedding-nomic-embed-text-v1.5"      # check the id with /v1/models
NOTES, MAX, OVERLAP = pathlib.Path("notes"), 1500, 200


def chunk_file(path):
    text = path.read_text(encoding="utf-8", errors="ignore")
    sections = re.split(r"(?m)^(#{1,3} .*)$", text)       # keep headings as separators
    heading, chunks = "", []
    for part in sections:
        if re.match(r"^#{1,3} ", part):
            heading = part.strip("# ").strip()
            continue
        body = part.strip()
        start = 0
        while start < len(body):
            piece = body[start:start + MAX]
            chunks.append(f"[{path.name} > {heading}]\n{piece}")
            start += MAX - OVERLAP
    return chunks


chunks = [c for f in sorted(NOTES.glob("*.md")) + sorted(NOTES.glob("*.txt")) for c in chunk_file(f)]
vectors = []
for i in range(0, len(chunks), 32):                       # embed in batches
    batch = ["search_document: " + c for c in chunks[i:i + 32]]
    vectors += [d.embedding for d in client.embeddings.create(model=EMBED, input=batch).data]
v = np.array(vectors, dtype=np.float32)
v /= np.linalg.norm(v, axis=1, keepdims=True)             # normalise once, so dot product = cosine
np.savez("index.npz", vectors=v, chunks=np.array(chunks, dtype=object))
print(f"indexed {len(chunks)} chunks from {NOTES}")

ask_docs.py

"""ask_docs.py: answer a question from your indexed notes, with citations."""
import sys
import numpy as np
from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")
EMBED, CHAT, TOP_K = "text-embedding-nomic-embed-text-v1.5", "your-chat-model-id", 4

idx = np.load("index.npz", allow_pickle=True)
vectors, chunks = idx["vectors"], idx["chunks"]
question = " ".join(sys.argv[1:]) or "What did I write about backups?"
q = np.array(client.embeddings.create(model=EMBED, input=["search_query: " + question]).data[0].embedding)
q /= np.linalg.norm(q)
scores = vectors @ q
best = np.argsort(-scores)[:TOP_K]
sources = "\n\n".join(f"[{n + 1}] {chunks[i]}" for n, i in enumerate(best))
for n, i in enumerate(best):
    print(f"[{n + 1}] score {scores[i]:.3f}  {chunks[i].splitlines()[0]}")

reply = client.chat.completions.create(model=CHAT, temperature=0.2, messages=[
    {"role": "system", "content": "Answer only from the numbered sources. Cite them like [1]. "
                                  "If the sources do not contain the answer, say you don't know."},
    {"role": "user", "content": f"Sources:\n{sources}\n\nQuestion: {question}"}])
print("\n" + reply.choices[0].message.content)

When results are poor

  • Check retrieval first. The printed sources show what was found. If the right chunk is not in the top 4, the chat model never had a chance.
  • Exact strings (error codes, product IDs, names) are a weak spot for embeddings. Production systems add keyword search (BM25) and merge the two rankings, called hybrid search.
  • Reranking: retrieve 20 chunks, then let a small reranker model pick the best 4.
  • Measure: write 20 questions whose answer you know is in a specific file, and count how often that file appears in the top 4. Change one thing at a time.
No code needed?

LM Studio can attach files to a chat and does simple RAG for you. Great for one-off questions. Your own scripts give you control, citations and evaluation.

Check yourself

What do all memory systems have in common?

  1. They change the model's weights
  2. They decide which text to place in the context
  3. They need a second GPU

The model is frozen. Memory is about choosing what text it sees.

You switched to a new embedding model and results got worse. Why?

  1. Old document vectors and new query vectors come from different models, so you must re-embed everything
  2. The chat model is too small
  3. Cosine similarity stopped working

Vectors from different embedding models are not comparable.

The answer is wrong. What do you check first?

  1. The temperature
  2. The GPU driver
  3. Whether the right chunk appeared in the retrieved sources

If retrieval misses, generation cannot recover.
