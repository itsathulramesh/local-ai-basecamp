Parameters, precision and quantization

A 9-billion-parameter model sounds like it must be enormous. How big it is on disk and in memory depends on how many bits each number uses. Shrinking the bits is called quantization, and it is the trick that lets big models fit on small cards.

What you will learn

  • Compute a model's size from its parameter count and precision
  • Explain what quantization is and what it costs in quality
  • Quantize a block of weights by hand and see where the error comes from
  • Read names like Q4_K_M and Q8_0
  • Choose a sensible quantization for your VRAM

Size = parameters × bits per weight

Each weight is a number, and a number takes memory. Models are usually trained in 16-bit precision (2 bytes per weight). So a 9B model at 16 bits is about 9 × 2 = 18 GB. A 70B model is 140 GB. That is too big for any home graphics card.

Concept: quantization

Quantization stores each weight with fewer bits, for example 4 bits instead of 16. The model becomes about four times smaller. Because the weights are stored less precisely, there is a small loss of quality. It is like saving a photo as JPEG: much smaller, and for most purposes you cannot tell.

The formula

Size in GB ≈ parameters (in billions) × bits per weight ÷ 8.

Example: 9B at Q4_K_M, which averages about 4.9 bits per weight: 9 × 4.9 ÷ 8 ≈ 5.5 GB. A real 9B Q4_K_M file measures about 5.6 GB, which matches.

How quantization works

Quantization stores each weight as a small integer plus a shared scale. To use a weight, the runtime multiplies the integer by the scale. Weights are handled in small blocks (32 or 256 weights in llama.cpp), each with its own scale, so one unusual value only affects its own block.

Worked example: eight weights to 4 bits

Take a block of eight weights: [0.20, −0.35, 0.10, 0.04, −0.15, 0.70, −0.22, 0.30]. Four bits gives 16 integer levels, −8 to 7.

  1. Scale. Map the largest magnitude (0.70) to 7: scale = 0.70 ÷ 7 = 0.10.
  2. Round. Divide each weight by the scale and round to the nearest integer.
  3. Dequantize. Multiply back: the model computes with these values.

The typical (root-mean-square) error is about 0.03, roughly 12% of an average weight here. Notice that the tiny weight 0.04 became exactly zero.

  • Storage. 8 weights × 4 bits plus one 16-bit scale = 48 bits, or 6 bits per weight. With blocks of 32, the scale is shared more widely: (32 × 4 + 16) ÷ 32 = 4.5 bits per weight. That is exactly llama.cpp's Q4_0 layout.
  • The outlier problem. Change 0.70 to 0.32 and the scale halves, so the grid is finer and the error drops to about a third. One big weight stretches the grid for its whole block. This is why real schemes use small blocks and keep sensitive layers at higher precision.
  • Scale plus minimum. Mapping the block's actual range (−0.35 to 0.70) onto the 16 levels instead of a symmetric grid cuts the error by about 40% here. The K-quants (Q4_K_M and friends) use this idea, with blocks grouped into "super-blocks".
  • Importance matrix (imatrix). Statistics from running the model on sample text tell the quantizer which weights matter most, so it spends precision where it counts. Files labelled "imatrix" or "i1" usually lose less quality at 4 bits and below.

Reading quantization names

The popular format for local models is GGUF. Its quantization names look like Q4_K_M:

  • Q4: about 4 bits per weight on average.
  • K: the "K-quant" method, which gives more bits to the most sensitive parts.
  • M (medium): a size variant. S is small, L is large.
  • Q8_0: 8 bits, an older simple scheme. Near-lossless.
  • F16 or BF16: the original 16-bit precision.
  • Names like IQ3_XS use cleverer compression for very low bit counts.
  • MXFP4: a 4-bit floating-point format some newer models are released in directly.

How quality loss is measured

  • Perplexity (PPL): how surprised the model is by real text. Lower is better. For quantization you look at the increase compared with the original.
  • KL divergence (KLD): how different the quantized model's whole probability distribution is from the original's at each step. Zero means identical. It catches changes perplexity can hide.

A note on 16-bit formats

Training normally uses BF16, a 16-bit floating-point format with the same range as 32-bit numbers but less precision. The older FP16 has more precision but a much smaller range, so large values can overflow during training. That is why you will see bf16 in training scripts and in conversion commands (lesson 9.6).

The golden rule

A bigger model at Q4 usually beats a smaller model at Q8. A 14B model at Q4 (about 8.5 GB) is typically better than a 7B model at Q8 (about 7.5 GB). So the best use of your VRAM is to pick the biggest model that fits at around Q4 to Q5, then spend leftover memory on context.

The exception is very small models (under about 4B). They suffer more from aggressive compression, so use Q6 or Q8 for them if they fit.

Which usually gives better results on the same 8 GB card?

  1. A 3B model at F16
  2. A 1B model at Q8
  3. A 9B model at Q4

Parameter count matters more than precision once you are at about 4 bits.

What does the "K" in Q4_K_M mean?

  1. The K-quant method, which spends more bits on sensitive weights
  2. 1,000 parameters
  3. The model has been keyed to your GPU

It names the quantization method, not a hardware setting.
