Build your training dataset

Your fine-tune can never be better than its data. A dataset is a specification of behaviour, written as examples. This lesson covers the file format, how many examples you need, where they can come from, and a script that turns your own notes into a clean dataset using your local model as a teacher.

What you will learn

  • Write examples in the chat JSONL format trainers expect
  • Judge how much data a goal needs and what "quality" means
  • Generate synthetic examples with a local teacher model, then clean and split them
  • Produce train.jsonl, valid.jsonl and test.jsonl

The format: chat JSONL

JSONL means one complete JSON object per line. Each line is one example conversation:

{"messages": [{"role": "system", "content": "You are my house-style editor."}, {"role": "user", "content": "Rewrite: the meeting got moved cause of the outage"}, {"role": "assistant", "content": "The meeting has been rescheduled because of the outage."}]}

Use this chat format by default. The trainer renders each example with the model's own chat template (lesson 7.3) and computes the loss only on the assistant's reply. Two other formats exist: {"prompt": ..., "completion": ...} pairs, and {"text": ...} for raw text when you want the model to continue documents (continued pretraining, lesson 9.7).

Watch the length

Examples longer than the training sequence length get truncated, so the model learns answers that stop mid-sentence. Estimate 1 token ≈ 4 characters and drop or split long examples before training.

How much data?

GoalTypical size
Lock in a format or house style100 to 500 examples
A narrow task skill500 to 3,000
A broad domain assistant5,000 and up, mixed with general data

Quality beats quantity. A well-known 2023 study (LIMA) fine-tuned a strong base model on only 1,000 carefully chosen examples and got results that held up against far larger datasets. Every inconsistency in your data is also learned.

What quality means

  • Correct. Every claim true. If 10% of answers contain an invented fact, the model learns that inventing is part of the job.
  • Consistent. Same system prompt, same headings, same tone in every example.
  • Representative. Inputs look like what you will really type.
  • Diverse. Many topics, lengths and phrasings, so the model learns the pattern, not the instances.
  • Honest. Include examples where the right answer is "I don't know" or "not enough information".

Where data can come from

  • Your own writing: notes, emails, documents, code you wrote. The best source, because it is your voice.
  • Openly licensed datasets on Hugging Face. Check each licence. Some forbid commercial use.
  • Synthetic data drafted by a model and reviewed by you.
  • Never other people's private data, credentials, client documents, or a benchmark you plan to evaluate on. Training on your test set makes your scores meaningless.
Teacher models and terms of service

If a cloud model (OpenAI, Anthropic, Google) drafts your examples, check its current terms. Several providers restrict using outputs to build competing models. A local open-weight teacher avoids that question and keeps your data private.

Synthetic data with a local teacher

The teacher writes examples; the student is the model you train. The safest pattern with a small local teacher is grounded generation: give it a chunk of your text and ask for question-and-answer pairs whose facts come only from that chunk. Your text supplies correctness. The model supplies phrasing and variety. LM Studio can force the reply into an exact JSON shape (structured output), which makes parsing reliable.

The script: make_dataset.py

Put your notes as .md or .txt files in ai-lab\finetune\notes. Start LM Studio's server with a capable model loaded (lesson 6.2). Edit SYSTEM and STYLE, then run.

"""Turn your notes into chat-format train/valid/test JSONL using a local teacher model."""
import argparse, hashlib, json, pathlib, random, re
from openai import OpenAI

SYSTEM = "You are a helpful assistant that answers in my personal style."   # the prompt your fine-tune will use
STYLE = "Answer clearly in 2-5 sentences, plain English, no bullet lists."   # how answers should read
SCHEMA = {"type": "object", "properties": {"pairs": {"type": "array", "items": {
    "type": "object", "properties": {"question": {"type": "string"}, "answer": {"type": "string"}},
    "required": ["question", "answer"]}}}, "required": ["pairs"]}
SECRETS = [r"-----BEGIN [A-Z ]*PRIVATE KEY-----", r"AKIA[0-9A-Z]{16}", r"eyJ[\w-]+\.[\w-]+\.[\w-]+",
           r"(?i)(password|api[_-]?key|token)\s*[:=]\s*\S+", r"[\w.+-]+@[\w-]+\.[\w.]+"]


def chunks(text, size=2500):
    buf = ""
    for para in re.split(r"\n\s*\n", text):
        if len(buf) + len(para) > size and buf:
            yield buf
            buf = ""
        buf += para + "\n\n"
    if buf.strip():
        yield buf


def scrub(s):
    for pat in SECRETS:
        s = re.sub(pat, "[REDACTED]", s)
    return s


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--notes", default="notes")
    ap.add_argument("--out", default="data")
    ap.add_argument("--model", default="local-model")
    ap.add_argument("--per-chunk", type=int, default=4)
    a = ap.parse_args()
    client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")
    by_source, seen = {}, set()
    for f in sorted(pathlib.Path(a.notes).glob("*.*")):
        if f.suffix.lower() not in {".md", ".txt"}:
            continue
        for chunk in chunks(scrub(f.read_text(encoding="utf-8", errors="ignore"))):
            prompt = (f"From the text below, write {a.per_chunk} varied question-and-answer pairs. "
                      f"Use ONLY facts stated in the text. {STYLE}\n\nTEXT:\n\"\"\"\n{chunk}\n\"\"\"")
            r = client.chat.completions.create(
                model=a.model, temperature=0.7,
                messages=[{"role": "user", "content": prompt}],
                response_format={"type": "json_schema", "json_schema": {"name": "qa", "schema": SCHEMA}})
            try:
                pairs = json.loads(r.choices[0].message.content)["pairs"]
            except (json.JSONDecodeError, KeyError, TypeError):
                continue
            for p in pairs:
                q, ans = scrub(p["question"].strip()), scrub(p["answer"].strip())
                key = hashlib.md5(re.sub(r"\W+", " ", q.lower()).encode()).hexdigest()
                if len(ans) < 40 or len(q) < 10 or key in seen:
                    continue
                seen.add(key)
                by_source.setdefault(f.name, []).append({"messages": [
                    {"role": "system", "content": SYSTEM},
                    {"role": "user", "content": q},
                    {"role": "assistant", "content": ans}], "source": f.name})
        print(f"{f.name}: {len(by_source.get(f.name, []))} examples")

    sources = list(by_source)
    random.Random(0).shuffle(sources)
    n = len(sources)
    split = {"test": sources[:max(1, n // 10)], "valid": sources[max(1, n // 10):max(2, n // 5)]}
    split["train"] = [s for s in sources if s not in split["test"] + split["valid"]]
    out = pathlib.Path(a.out)
    out.mkdir(exist_ok=True)
    for name, srcs in split.items():
        rows = [r for s in srcs for r in by_source[s]]
        with open(out / f"{name}.jsonl", "w", encoding="utf-8") as fh:
            for r in rows:
                fh.write(json.dumps(r, ensure_ascii=False) + "\n")
        print(f"{name}: {len(rows)} examples from {len(srcs)} files")


if __name__ == "__main__":
    main()

python make_dataset.py --notes notes --out data --model "the-model-id-from-LM-Studio"

Clean before you train

  1. Validate. Every line parses, every example has system, user and assistant.
  2. Filter lengths. The script drops very short answers. Also drop ones too long for your sequence length.
  3. Scrub secrets and personal data. The script catches common patterns. Add your own names and domains.
  4. Deduplicate. Duplicates silently over-weight one example.
  5. Make the style consistent. One system prompt, one tone.
  6. Read at least 30 to 50 random examples yourself. Fix or delete bad ones. Nothing replaces this.

Splits and leakage

The script splits by source file, about 80/10/10. If one document produced ten examples and they landed in both train and test, your test would measure memorisation, not skill. valid.jsonl is checked during training to spot overfitting. test.jsonl is touched only once, at the end (lesson 9.5).

Lab
  1. Collect 10 to 30 documents of your own writing into notes.
  2. Run the script and open train.jsonl in VS Code.
  3. Review 30 examples. Delete anything wrong. Note what the teacher got wrong most often and adjust STYLE.
  4. Aim for at least 200 good training examples before moving on.

Check yourself

Why split by source document rather than by example?

  1. To stop near-identical examples from one document leaking into the test set
  2. To make training faster
  3. Because trainers require it

Leakage makes the test measure memorisation instead of skill.

What does grounded generation protect against?

  1. Slow training
  2. Large files
  3. The teacher inventing facts, since facts must come from your supplied text

Your text supplies correctness. The model only phrases it.

500 examples, 50 of which contain wrong facts. What does the model learn?

  1. To ignore the wrong ones automatically
  2. That stating wrong facts confidently is part of the job
  3. Nothing, the dataset is too small

Everything in the data is learned, including mistakes.
