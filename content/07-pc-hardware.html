Almost every question about local AI comes down to one number: how much video memory your graphics card has. This lesson explains the parts of your PC, which ones matter, and how to read your own specs.

What you will learn

  • Say what the CPU, RAM, GPU and VRAM each do for a language model
  • Explain why VRAM and memory bandwidth matter more than anything else
  • Find your own graphics card, VRAM and RAM in Windows

The four parts

PartWhat it isRole for local AI
CPUThe general-purpose processorCan run models by itself, but slowly. Handles everything the GPU does not.
RAMSystem memory (for example 16 or 32 GB)Holds whatever does not fit on the GPU. Much slower to use for AI than VRAM.
GPUThe graphics processor, with thousands of small coresDoes the heavy arithmetic of a model many times faster than a CPU.
VRAMThe GPU's own fast memory (for example 8, 12 or 24 GB)The model's weights must live here to run fast. This is the limiting resource.
Concept: VRAM sets the speed, VRAM + RAM sets the limit

A model runs fastest when all of its weights and working memory sit in VRAM. If it does not fit, LM Studio and Ollama put as many layers as they can on the GPU and run the rest from system RAM on the CPU. That works, just more slowly. So two questions decide what you can run: does it fit in VRAM (fast), or in VRAM plus free system RAM (works, slower)? Module 3 teaches you to answer both with arithmetic.

Why memory bandwidth matters

To produce each token, the GPU must read essentially all the model's weights from memory once. So the speed of generation is limited by how fast memory can be read, called memory bandwidth and measured in GB/s, rather than by raw computing power. A card with twice the bandwidth generates roughly twice as fast with the same model. Lesson 3.4 turns this into a speed estimate.

Here is why this matters when shopping or comparing: two cards with the same VRAM can feel very different. A card with a narrow memory bus can be several times slower than one with a wide bus.

Why NVIDIA?

NVIDIA GPUs use a software platform called CUDA. Almost every AI tool is built first for CUDA: LM Studio and Ollama use it to accelerate models, PyTorch uses it for training, and fine-tuning libraries such as Unsloth rely on it. AMD and Intel GPUs also work in several tools, but NVIDIA has the smoothest path, and it is what the rest of this course assumes.

Find out what you have

On your PC
  1. Press Ctrl+Shift+Esc to open Task Manager and click Performance.
  2. Click GPU (there may be two: a weak integrated one and your NVIDIA card). Note the name, Dedicated GPU memory (this is your VRAM) and the driver version.
  3. Click Memory and note total RAM and speed.
  4. Click CPU and note the model name.

Or from a terminal, once the driver is installed (next lesson):

nvidia-smi --query-gpu=name,driver_version,memory.total,memory.used --format=csv

Write the result in your NOTES.md. You will need these numbers in nearly every later lesson.

Laptops

Laptop GPUs often have less VRAM than the desktop card with the same name, and may be throttled by heat. Windows can also switch between the integrated and NVIDIA GPU. In the NVIDIA Control Panel or Windows Graphics settings you can set the AI app to use the NVIDIA GPU.

Pick your card

Choose your graphics card to see its VRAM and bandwidth and a rough idea of what it can run. Figures are approximate.

Check yourself

What decides whether a model runs fast on your PC?

  1. The number of CPU cores
  2. How much storage space you have
  3. Whether the model fits in your VRAM

Models that fit in VRAM run on the GPU at full speed. Spilling to system RAM is far slower.

Two GPUs both have 12 GB. One has double the memory bandwidth. Which generates tokens faster with the same model?

  1. The higher-bandwidth one, roughly twice as fast
  2. They are the same
  3. The one with the lower bandwidth

Generation reads all weights per token, so bandwidth sets the speed ceiling.
