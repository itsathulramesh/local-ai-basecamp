You already prompt cloud models. Smaller local models need a slightly different approach: clearer, more explicit and more structured. These habits improve results enormously.

What you will learn

  • Write a prompt with role, task, context and format
  • Use examples to control style and output
  • Ask for step-by-step reasoning when it helps
  • Fix common failure patterns

The four-part prompt

PartExample
RoleYou are a careful technical editor.
TaskSummarise the text below in five bullet points.
ContextThe audience is non-technical managers.
FormatReturn only a numbered list. No introduction.

Habits that help small models

  • Be explicit. Smaller models do not infer as much. Say what you want, in what length and shape.
  • Give one task at a time. Break a big job into steps and feed the results forward.
  • Show examples. Two or three input-output examples (few-shot prompting) teach the pattern better than a paragraph of description.
  • Use delimiters. Mark where the document begins and ends so instructions are not confused with content.
  • Ask for step-by-step thinking on logic and maths: "Work through it step by step, then give the final answer on a new line starting with ANSWER:".
  • Put instructions last as well. In long prompts, repeat the key instruction after the document.
  • Lower the temperature for precise tasks.

Structured output

When code needs to read the answer, ask for JSON and give the exact shape:

Return only valid JSON in this shape, with no other text:
{"sentiment": "positive|neutral|negative", "topics": ["..."], "confidence": 0.0}

Many tools, including LM Studio and Ollama, can also enforce a JSON schema so the model cannot produce anything else. Lesson 6.5 shows exactly how.

Common failures and fixes

SymptomFix
Rambling, long answersState a length limit, and say "Output only…"
Ignores part of the promptShorten it. Number the requirements.
Invents factsPaste the facts. Add "If the text does not say, answer UNKNOWN."
Wrong formatProvide an example of exactly the format
Inconsistent between runsLower temperature. Add examples.
Concept: prompts are programs

Save your best prompts in files, version them, and test changes on the same ten inputs. That is how professionals do it, and it is the basis for the evaluation work in lesson 9.5.

Check yourself

What most reliably teaches a small model a specific output pattern?

  1. A few input-output examples in the prompt
  2. Writing the prompt in capital letters
  3. Raising the temperature

Few-shot examples demonstrate the pattern directly.

How do you reduce invented facts when summarising a report?

  1. Ask the model to be creative
  2. Provide the report text and tell it to answer only from the text
  3. Increase context length only

Grounding the model in supplied text and allowing "unknown" cuts hallucination.
