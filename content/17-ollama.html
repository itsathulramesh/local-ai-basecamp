Ollama is the other popular way to run models. It has no chat window of its own, just a tiny command-line tool and a background server, which makes it the favourite for scripts and apps. Learning both tools makes you flexible.

What you will learn

  • Install Ollama and run a model in one command
  • Use the everyday commands
  • Know where models are stored and how to move them
  • Set context length, which Ollama keeps small by default

Install

Download OllamaSetup.exe from ollama.com/download. It installs for your user account without needing administrator rights, starts in the background (look for the llama icon in the tray), and adds ollama to your terminal. The documentation lists Windows 10 22H2 or newer and NVIDIA driver 551.61 or newer. Or:

winget install Ollama.Ollama

First run

ollama run llama3.2

The first time, it downloads the model, then opens an interactive chat. Type /bye to leave. Browse the model list at ollama.com/library. Names look like name:size, for example llama3.2:3b. A name with no tag uses a default size.

Everyday commands

ollama pull MODEL        # download without chatting
ollama list              # models on disk
ollama ps                # models loaded now, with VRAM use and CPU/GPU split
ollama show MODEL        # details: size, quantization, context, template
ollama run MODEL --verbose   # prints speed after each reply
ollama stop MODEL        # unload from memory
ollama rm MODEL          # delete from disk
Concept: ollama ps is your friend

The PROCESSOR column in ollama ps says for example 100% GPU or 35%/65% CPU/GPU. If any part says CPU, the model did not fully fit and you are in the slow spill zone from lesson 3.3.

Where the models live

By default in %HOMEPATH%\.ollama. Models are large, so many people move them to a bigger drive by setting a user environment variable, then restarting Ollama from the tray:

[Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\ollama\models", "User")

Context length

On GPUs with less than 24 GB of memory, Ollama has historically used a small default context window (around 4,096 tokens), which silently truncates long prompts. Raise it explicitly:

[Environment]::SetEnvironmentVariable("OLLAMA_CONTEXT_LENGTH", "8192", "User")

Or inside a chat: /set parameter num_ctx 8192. Check the current Ollama docs for the exact default, which has changed between versions.

The server

Ollama's server listens on http://localhost:11434. Any program on your PC can call it. Lesson 6.2 shows how. By default it only accepts connections from your own machine, which is what you want.

Do not expose it to the network

Setting OLLAMA_HOST=0.0.0.0 makes it reachable from other devices. The server has no login, so anyone who can reach it can use your GPU and your models. Only do this inside a trusted network or behind a proper authentication proxy.

Modelfiles

A Modelfile bundles a model with your settings and system prompt as a reusable custom model:

FROM llama3.2
SYSTEM You are a concise technical tutor. Answer in plain English.
PARAMETER temperature 0.4
PARAMETER num_ctx 8192
ollama create tutor -f Modelfile
ollama run tutor

Check yourself

Which command shows whether a loaded model is fully on the GPU?

  1. ollama list
  2. ollama ps
  3. ollama rm

ollama ps shows the GPU/CPU split for loaded models.

Why set the context length in Ollama explicitly?

  1. To change the model's weights
  2. To make downloads faster
  3. The default may be small and silently cut off long prompts

A small default window means anything past it is dropped.
