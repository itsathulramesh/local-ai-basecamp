Two more ways to change weights without a full training run: surgically rewriting a single fact, and blending several fine-tunes into one model. Both are useful to know about, and merging in particular is popular in the open-model community.

What you will learn

  • Explain how ROME and MEMIT rewrite facts, and their limits
  • Explain task arithmetic and the main merge methods
  • Know when merging beats another fine-tune

MLPs as key-value memories

Lesson 7.2 mentioned that MLPs behave a bit like memories: a pattern in the input (the key, such as "the capital of France is") retrieves a stored output (the value, "Paris"). Knowledge-editing methods use this view.

ROME and MEMIT

  • ROME (2022) locates the MLP layer that stores a fact and applies a rank-one update to its weights so one key retrieves a new value. Change "the Eiffel Tower is in Paris" to "Rome" and related questions follow.
  • MEMIT extends this to thousands of edits at once across several layers.
Limits

Edits can be brittle: they may not carry over to rephrased questions or related facts, and many edits can degrade the model. For keeping a model up to date with facts, RAG remains the practical answer (lesson 8.1). Treat knowledge editing as a research tool.

Task arithmetic

If you fine-tune a base model and subtract the base weights from the result, you get a task vector: the change that skill made. Task vectors can be added (combine skills), scaled (stronger or weaker), or subtracted (remove a behaviour). A LoRA adapter is a compact, low-rank task vector.

Model merging

Merging combines models that share the same base and architecture into one, with no training.

MethodIdea
LinearWeighted average of the weights
SLERPInterpolates two models along a curve instead of a straight line, often smoother
TIESKeeps only the largest changes from each fine-tune and resolves sign conflicts
DARERandomly drops most small changes and rescales the rest before merging

The common tool is mergekit. A merge is described in a small YAML file listing the models, the method and the weights, and runs on CPU if needed. Many popular community models on Hugging Face are merges.

# mergekit example (check its README for current syntax)
merge_method: ties
base_model: Qwen/Qwen3-4B
models:
  - model: you/qwen3-4b-housestyle-merged
    parameters: {weight: 0.6, density: 0.5}
  - model: someone/qwen3-4b-coder-finetune
    parameters: {weight: 0.4, density: 0.5}
dtype: bfloat16

When to merge

  • You have two fine-tunes of the same base (for example your house style and a coding skill) and want both.
  • You want to soften a fine-tune by merging it back toward the base.
  • Combining several LoRA adapters: PEFT can merge adapters (add_weighted_adapter), and llama.cpp's server can stack several at chosen scales.

Evaluate a merge exactly like a fine-tune (lesson 9.5). Merges can be surprisingly good or quietly broken.

Check yourself

Can you merge a Llama fine-tune with a Qwen fine-tune?

  1. Yes, with SLERP
  2. Yes, with TIES
  3. No. Merged models must share the same base architecture.

Weights only line up between models of the same architecture and base.

What is a task vector?

  1. Fine-tuned weights minus base weights
  2. A list of tasks
  3. A steering vector

It captures the change a fine-tune made, and can be added, scaled or subtracted.
