From logits to probabilities

At each step the model outputs one raw score, a logit, for every token in its vocabulary (often 150,000 to 250,000 of them). Scores can be any number. Softmax turns them into probabilities: raise e to each score, then divide by the total so everything adds up to 1.

Temperature (lesson 4.2) divides every logit before softmax. Dividing by 0.5 doubles the gaps, so Paris takes almost everything. Dividing by 1.5 shrinks the gaps, so the others get a real chance.

Picking a token

  • Greedy decoding always takes the top token. Deterministic, good for extraction and code, but prone to bland, repetitive text.
  • Sampling draws a token at random according to the probabilities, after filters like top-k, top-p and min-p (lesson 4.2). Natural-sounding, slightly different every time.
  • A fixed seed makes sampling repeatable, which is useful when you compare settings.

The autoregressive loop

  1. Tokenize the prompt (with the chat template, lesson 7.3).
  2. Run the model, get logits for the next position, pick a token.
  3. Append the token to the input and repeat.
  4. Stop when a stop condition is met.

"Autoregressive" means each new token depends on all previous ones, including the ones the model just wrote. That is why it cannot go back and fix an earlier sentence.

The KV cache

Without a cache, every new token would require recomputing attention for the whole conversation. Instead the model stores each processed token's keys and values (lesson 7.2) and only computes the new token's. That is the KV cache: it turns quadratic work into roughly constant work per token, at the cost of VRAM that grows with context (lesson 3.3). It is also why sending a long conversation again is cheaper when the runtime can reuse a cached prefix.

How generation stops

  • The model produces the end-of-sequence or end-of-turn token. This is the normal way.
  • A maximum token limit is reached (max_tokens). The answer is cut off.
  • A stop string you configured appears.

If the template is wrong, the model never produces a recognised stop token and keeps talking (lesson 7.3).

Repetition loops

Small models, low temperatures and long reasoning chains can fall into loops: once a phrase repeats, it becomes the most likely continuation of itself. Fixes, in order: use the sampling values on the model card, raise temperature slightly, add a small repeat or presence penalty (about 1.05 to 1.1), shorten the context, or switch to a larger model. Module 10 shows that loops can even correspond to a direction you can remove from the weights.

Watch it happen

This script runs greedy decoding by hand and prints the top candidates at each step. Run it in the AI Python environment from lesson 2.3. It takes seconds on your GPU:

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

name = "Qwen/Qwen3-0.6B"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name, dtype=(torch.bfloat16 if torch.cuda.is_bf16_supported() else torch.float16), device_map="cuda")
text = tok.apply_chat_template([{"role": "user", "content": "The capital of France is?"}],
                               tokenize=False, add_generation_prompt=True, enable_thinking=False)
ids = tok(text, return_tensors="pt").input_ids.to("cuda")
for step in range(8):
    with torch.no_grad():
        logits = model(ids).logits[0, -1].float()
    probs = torch.softmax(logits, dim=-1)
    top = torch.topk(probs, 5)
    shown = ", ".join(f"{tok.decode(int(i))!r} {p:.2f}" for p, i in zip(top.values, top.indices))
    print(f"step {step}: {shown}")
    ids = torch.cat([ids, top.indices[:1].view(1, 1)], dim=1)      # greedy: take the top token
print(tok.decode(ids[0], skip_special_tokens=True))

This simple loop has no KV cache, so it recomputes everything each step. That is fine for 8 tokens and a good illustration of why real runtimes cache.

Check yourself

Why is the first token slower to appear when you paste a long document?

  1. The model is downloading
  2. Prefill must process every prompt token before decoding starts
  3. Temperature is too high

Time to first token grows with prompt length.

What does the KV cache save?

  1. Recomputing keys and values for all earlier tokens at every step
  2. Disk space
  3. The model's weights

It trades VRAM for much less computation per token.

A reply ends mid-sentence. Which stop condition most likely fired?

  1. End-of-sequence token
  2. A stop string
  3. The maximum token limit

Raise max_tokens if answers are cut off.
