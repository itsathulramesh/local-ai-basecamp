Chatting in an app is fun. The real power arrives when your own scripts can call the model. Both LM Studio and Ollama run a local web server that speaks the same API as OpenAI, so almost any tutorial code works with a one-line change.

What you will learn

  • Start the LM Studio and Ollama servers
  • Call them from Python with the OpenAI library and with plain requests
  • Stream tokens as they are generated
  • Build a small reusable function you will use in later modules

Your first call

cd $HOME\ai-lab
.venv\Scripts\Activate.ps1
pip install openai
from openai import OpenAI

# LM Studio: port 1234.  Ollama: use "http://localhost:11434/v1"
client = OpenAI(base_url="http://localhost:1234/v1", api_key="not-needed")

reply = client.chat.completions.create(
    model="your-model-name",          # copy from the app or "ollama list"
    messages=[
        {"role": "system", "content": "You are a concise tutor."},
        {"role": "user", "content": "Explain VRAM in two sentences."},
    ],
    temperature=0.3,
)
print(reply.choices[0].message.content)
Concept: messages are the memory

The model has no memory between calls. To continue a conversation, you append each answer and each new question to the messages list and send the whole list again. This is exactly the "context window as memory" idea from lesson 1.4, now written in code.

A tiny chat loop

from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="x")
messages = [{"role": "system", "content": "You are a friendly tutor."}]

while True:
    user = input("You: ")
    if user.strip().lower() in {"quit", "exit"}:
        break
    messages.append({"role": "user", "content": user})
    out = client.chat.completions.create(model="your-model-name", messages=messages)
    text = out.choices[0].message.content
    print("AI:", text)
    messages.append({"role": "assistant", "content": text})

Notice the list keeps growing. After many turns it will approach the context limit. That is why long chats degrade.

Streaming

stream = client.chat.completions.create(
    model="your-model-name",
    messages=[{"role": "user", "content": "Write a haiku about GPUs."}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)
print()

Measure speed in code

import time
start = time.time()
out = client.chat.completions.create(
    model="your-model-name",
    messages=[{"role": "user", "content": "Write 150 words about oceans."}],
)
secs = time.time() - start
tokens = out.usage.completion_tokens
print(f"{tokens} tokens in {secs:.1f}s = {tokens/secs:.1f} tokens/sec")

Native Ollama API

Ollama also has its own simpler endpoint:

import requests
r = requests.post("http://localhost:11434/api/generate",
                  json={"model": "llama3.2", "prompt": "Why is the sky blue?", "stream": False},
                  timeout=300)
print(r.json()["response"])
Mini project

Write ask.py: it reads a text file from the command line, sends it to your model with a summarising prompt at temperature 0.2, prints the summary and the tokens per second. Run it on three files. Save it in ai-lab. You will reuse the pattern constantly.

Keep it local

The examples use localhost, which only your own PC can reach. Do not change the address to your network address unless you understand the security implications (lesson 6.4).

Check yourself

To continue a conversation through the API you must:

  1. Wait for the model to remember
  2. Reload the model every time
  3. Send the earlier messages again in the messages list

The API is stateless. You supply the history each time.

What must change when moving the OpenAI-library code from LM Studio to Ollama?

  1. The base URL (port) and the model name
  2. The whole library
  3. Nothing at all

Both speak the same API, so only the address and model name differ.
