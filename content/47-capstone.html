Time to prove it. In this project you build a model that is genuinely yours: trained on your data, in your style, free of the refusals that get in your way, packaged and served on your own PC. Each step points to the lesson that taught it.

What you will deliver

  • A written spec and a reviewed dataset
  • A trained LoRA, evaluated against the base model
  • An uncensored variant made by one of the routes in lesson 10.4
  • A named custom model in Ollama and LM Studio, called from a Python script

Pick a project

Choose something you will actually use. Good first projects:

  • Your writing twin: rewrites drafts in your tone and format.
  • A domain explainer: explains your field in plain English in a consistent structure, without hedging.
  • A strict formatter: turns messy notes into a fixed JSON or report structure every time.
  • A fiction partner: writes in a chosen style without over-refusing dark themes.

Step 1: write the spec (30 minutes)

One page in NOTES.md: what the model does, what a perfect answer looks like (write three), what it must never do, which base model and size fits your GPU (lesson 9.1), and how you will judge success (lesson 9.5).

Step 2: baseline (1 hour)

Before training anything, try the cheaper rungs (lesson 8.1). Write the best system prompt you can, make a Modelfile (lesson 8.2), and score the base model on 20 test prompts. This is the bar your fine-tune must beat. If the prompt alone is good enough, you have learned something valuable cheaply.

Step 3: dataset (an evening or two)

Use make_dataset.py (lesson 9.2) on your own documents, then review by hand. Target 300 or more training examples. If your domain is over-refused, include direct, complete answers for those requests (route 3 in lesson 10.4). Keep 10% aside as test data.

Step 4: train (1 to 3 hours)

Run train_lora.py in WSL2 (lessons 9.3 and 9.4). Do one quick run on a small model or a subset first to check the pipeline. Keep a run log: settings, losses, verdict.

Step 5: evaluate (1 hour)

Blind A/B against the baseline on the test set, plus the regression set (lesson 9.5). If it does not clearly win, fix the data before changing hyperparameters. Data is almost always the problem.

Step 6: uncensor (1 to 3 hours)

Pick a route from lesson 10.4. Route 1 if a suitable abliterated safetensors base exists, route 2 if you want to do the abliteration yourself with ablate.py (lesson 10.3). Measure the refusal rate on held-out legitimate prompts and rerun the regression set.

Step 7: package and serve (30 minutes)

  1. Export to GGUF and check the template (lesson 9.6).
  2. Make a Modelfile with your system prompt and settings, then ollama create (lesson 8.2).
  3. Import into LM Studio with a preset.
  4. Call it from ask.py (lesson 6.2).

Step 8: write it up

A short model card in your ai-lab folder: base model and licence, data sources, training settings, evaluation results, uncensoring method, known weaknesses. This habit is what separates experiments from engineering.

Capstone checklist

If it does not beat the baseline

That is a normal first result. Read 20 training examples critically, fix inconsistencies, add variety, and retrain with the same settings. Change hyperparameters only after the data is good.
