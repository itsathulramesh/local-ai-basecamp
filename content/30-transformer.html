You will soon choose which parts of a model to train and which directions to remove from it. That only makes sense once you can picture what is inside. This lesson walks through one token's journey through a transformer, with no maths beyond addition and multiplication.

What you will learn

  • Follow a token from embedding to prediction
  • Explain the residual stream, attention and the MLP
  • Name the weight matrices you will target with LoRA and edit with ablation
  • Explain grouped-query attention, hybrid layers and mixture-of-experts at a high level

The big picture

  1. Embedding. Each token id is looked up in a table and becomes a vector, a list of a few thousand numbers (for example 4,096 for a 9B model, 1,024 for a 0.8B).
  2. A stack of blocks. The vector passes through dozens of identical-shaped blocks (layers). Each block has two parts: attention and an MLP.
  3. Prediction. The final vector is turned into a score for every token in the vocabulary. That is the "next token" output from lesson 1.1.

The residual stream: a shared bus

Here is the idea that makes everything else click. Each block does not replace the token's vector. It reads the vector, computes something, and adds its result back. The running vector is called the residual stream. Think of it as a shared bus or whiteboard that every layer reads from and writes to.

Concept: the residual stream

The token's vector after layer N equals the embedding plus everything every layer so far has added. Because it is a sum, a concept the model tracks often shows up as a direction in this space. Module 10 exploits exactly that: find the direction for a behaviour, then add it (steering) or delete it (ablation).

Attention: tokens looking at each other

A word's meaning depends on context. "Bank" means something different after "river" than after "loan". Attention lets each token pull information from earlier tokens.

  • Each token makes a query ("what am I looking for?"), a key ("what do I contain?") and a value ("what will I share?"). These are produced by three weight matrices called q_proj, k_proj and v_proj.
  • A token compares its query with every earlier token's key. High match means "pay attention to that one". It then takes a weighted mix of their values.
  • A fourth matrix, o_proj, writes the result back into the residual stream.
  • A causal mask stops a token from looking at later tokens, so the model cannot cheat by seeing the answer.
  • Multi-head attention runs many of these in parallel, each free to focus on a different kind of relationship.

The keys and values of previous tokens are exactly what the KV cache stores (lesson 3.3). That is why the cache grows with context.

Grouped-query attention (GQA)

Modern models let several query heads share one set of keys and values. With 32 query heads but 8 key/value heads, the KV cache is four times smaller. That "KV heads" number is what the lesson 3.3 calculator uses.

The MLP: where much of the knowledge lives

After attention, each token's vector goes through a small two-layer network applied to that token alone. It expands the vector to a much wider size (for example 4,096 to 12,288), applies a non-linear function, and squeezes it back down. In most current models the matrices are called gate_proj, up_proj and down_proj. Research suggests MLPs act a bit like key-value memories, storing many associations ("Paris" → "France"). down_proj is the matrix that writes the result into the residual stream.

Normalisation and position

  • RMSNorm rescales the vector before each part so numbers stay in a healthy range.
  • Position is injected so the model knows word order. Most current models use a method called RoPE, which rotates queries and keys by an angle that depends on position.

The "writers" (embed_tokens, o_proj, down_proj, and in hybrid models the linear-attention out_proj) are the only places anything enters the residual stream. Remember that, because abliteration edits exactly those.

Variations you will meet

  • Hybrid models. Some recent models, including the Qwen3.5 family, mix ordinary attention layers with "linear attention" layers (Gated DeltaNet) that keep a fixed-size running memory instead of a growing KV cache. In Qwen3.5 roughly three of every four layers are linear, which makes long context much cheaper. Their output matrix is called out_proj.
  • Mixture-of-experts. The MLP is replaced by many expert MLPs and a router picks a few per token (lesson 2.4).
  • Vision models. A separate vision encoder turns images into vectors that enter the same residual stream. In GGUF land that encoder ships as the mmproj file.

Count the parameters

A quick sanity check to run in the AI Python environment from lesson 2.3. It downloads only a small model's config and builds an empty skeleton, so it is fast and needs no GPU:

from accelerate import init_empty_weights
from transformers import AutoConfig, AutoModelForCausalLM

cfg = AutoConfig.from_pretrained("Qwen/Qwen3-0.6B")   # any small model id works
with init_empty_weights():
    model = AutoModelForCausalLM.from_config(cfg)
total = sum(p.numel() for p in model.parameters())
print(f"{total/1e9:.2f} B parameters")
for name, p in list(model.named_parameters())[:12]:
    print(name, tuple(p.shape))

Read the printed names. You will see embed_tokens, then layers.0.self_attn.q_proj and friends, then layers.0.mlp.down_proj. Those are the exact strings you will put in a LoRA config.

Check yourself

What does each transformer block do to the residual stream?

  1. Reads it and adds its own result to it
  2. Deletes it and writes a new one
  3. Nothing; only the last layer uses it

Every block adds to the running sum. That is why concepts appear as directions you can add or remove.

Which matrices write into the residual stream?

  1. q_proj and k_proj
  2. gate_proj and up_proj
  3. embed_tokens, o_proj and down_proj (plus out_proj in hybrid models)

Those are the "writers". Ablation edits them so a direction can never be written.

Why does grouped-query attention make long context cheaper?

  1. It removes the MLP
  2. Several query heads share keys and values, so the KV cache is smaller
  3. It skips half the tokens

Fewer KV heads means fewer numbers cached per token.
