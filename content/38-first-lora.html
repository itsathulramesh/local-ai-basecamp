This is the moment the course has been building to. You will load a small model, attach a LoRA adapter, train it on your dataset, test it, and save it, all on your own NVIDIA GPU. The same script scales to bigger models by changing one line.

What you will learn

  • Run the full Unsloth flow: load, attach LoRA, format, mask, train, test, save
  • Explain every hyperparameter you set
  • Read the training and validation loss
  • Adapt the script to other model families and sizes
Concept: Unsloth

An open-source library that speeds up and slims down fine-tuning by patching Hugging Face Transformers, PEFT and TRL. You write ordinary training code with Unsloth's model loader in front, and it can export straight to GGUF. It targets NVIDIA (and AMD) GPUs.

Choose your model

Start small so mistakes are cheap. Pick from the lesson 9.1 table:

  • 4 GB card (GTX 1650): unsloth/Qwen3.5-0.8B with MAX_LEN = 1024, batch size 1 and accumulation 8, or use free Colab for bigger models
  • 8 GB card: unsloth/Qwen3.5-2B (about 5 GB) or unsloth/Qwen3.5-0.8B
  • 12 to 16 GB: unsloth/Qwen3.5-4B (about 10 GB)
  • 24 GB: unsloth/Qwen3.5-9B with short sequences, or rent a bigger GPU

Model ids change. If an id is not found, search Hugging Face for the family under the unsloth organisation.

The script: train_lora.py

Save this inside WSL2 at ~/ai-lab/finetune/train_lora.py, next to your data folder.

from unsloth import FastLanguageModel          # import unsloth before transformers / trl
from unsloth.chat_templates import train_on_responses_only
from datasets import load_dataset
from trl import SFTTrainer, SFTConfig

MODEL = "unsloth/Qwen3.5-2B"     # change to fit your GPU (lesson 9.1)
MAX_LEN = 2048                   # must cover your longest example
OUT = "my-first-lora"

# 1. Load the base model in 16-bit (Unsloth advises against 4-bit QLoRA for Qwen3.5)
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name=MODEL, max_seq_length=MAX_LEN,
    load_in_4bit=False, load_in_16bit=True, full_finetuning=False)

# 2. Attach the LoRA adapter
model = FastLanguageModel.get_peft_model(
    model, r=16, lora_alpha=16, lora_dropout=0, bias="none",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj", "out_proj"],
    use_gradient_checkpointing="unsloth", random_state=3407, max_seq_length=MAX_LEN)
model.print_trainable_parameters()

# 3. Render each conversation with the model's own chat template
ds = load_dataset("json", data_files={"train": "data/train.jsonl", "validation": "data/valid.jsonl"})
def to_text(batch):
    return {"text": [tokenizer.apply_chat_template(m, tokenize=False, add_generation_prompt=False)
                     for m in batch["messages"]]}
ds = ds.map(to_text, batched=True, remove_columns=ds["train"].column_names)
print(ds["train"][0]["text"][:600])            # eyeball the rendered template

# 4. Trainer, then mask everything except the assistant replies
trainer = SFTTrainer(
    model=model, tokenizer=tokenizer,
    train_dataset=ds["train"], eval_dataset=ds["validation"],
    args=SFTConfig(
        dataset_text_field="text", max_length=MAX_LEN,
        per_device_train_batch_size=2, gradient_accumulation_steps=4,
        num_train_epochs=2, learning_rate=2e-4, warmup_steps=10,
        lr_scheduler_type="linear", optim="adamw_8bit", weight_decay=0.001,
        logging_steps=5, eval_strategy="steps", eval_steps=25, save_steps=25,
        output_dir="outputs", seed=3407, report_to="none"))
trainer = train_on_responses_only(trainer,
    instruction_part="<|im_start|>user\n", response_part="<|im_start|>assistant\n")

row = trainer.train_dataset[0]                 # check: only the answer should print
print(tokenizer.decode([t for t, l in zip(row["input_ids"], row["labels"]) if l != -100]))

trainer.train()

# 5. Quick test
FastLanguageModel.for_inference(model)
msgs = [{"role": "user", "content": "A question like the ones in your dataset"}]
ids = tokenizer.apply_chat_template(msgs, add_generation_prompt=True, return_tensors="pt",
                                    return_dict=True, enable_thinking=False).to("cuda")
out = model.generate(**ids, max_new_tokens=300, temperature=0.7, top_p=0.8)
print(tokenizer.decode(out[0][ids["input_ids"].shape[1]:], skip_special_tokens=True))

# 6. Save the adapter (small) and a ready-to-run GGUF
model.save_pretrained(OUT)
tokenizer.save_pretrained(OUT)
model.save_pretrained_gguf(OUT + "-gguf", tokenizer, quantization_method="q4_k_m")
cd ~/ai-lab/finetune && source .venv/bin/activate

Concept: train on responses only

Sets the label of every token outside the assistant replies to -100, a value the loss ignores. The model still reads the system prompt and the question but is only graded on writing the answer. The decoded check line should print only answers. The markers in instruction_part and response_part are for Qwen-style templates. Other families use different markers, so copy them from your printed template.

Common training errors

"no kernel image is available for execution"Your PyTorch build is too old for the GPU (common with RTX 50-series). Install the newest CUDA build from pytorch.org.

Long pause before step 1Normal on the first run while kernels compile. Wait a few minutes.
"bf16 not supported" or similarOlder GPUs (GTX 16, RTX 20, Colab T4) use float16. Let Unsloth choose the dtype automatically.

Reading the loss

What you seeMeaningAction
Both losses fall, then level offHealthyKeep the run
Training loss falls, validation loss risesOverfittingFewer epochs, use an earlier checkpoint, more data
Training loss near zeroMemorisingFewer epochs, lower learning rate
nan or sudden spikesLearning rate too highHalve it
Barely movesLearning rate too low, or masking wrongCheck the decoded mask line, raise learning rate
CUDA out of memoryToo big for your cardBatch 1, accumulation 8, shorter MAX_LEN, smaller model

Change one thing at a time

Keep a table in your notes: run name, model, data size, r, learning rate, epochs, final validation loss, and your verdict. Without it you cannot tell which change helped.

Thinking models

With Qwen3.5's template, examples without reasoning are rendered with an empty <think> block, which teaches the "thinking off" style. That matches running the model with thinking off. If you want your fine-tune to keep thinking, include reasoning in most examples (Unsloth suggests at least 75%) and evaluate with thinking on.

Other model families

  • Llama, Gemma, Mistral and many others: change MODEL, use load_in_4bit=True for QLoRA if you need the memory, and drop out_proj from the target list.
  • Change the instruction_part and response_part markers to that family's template.
  • Unsloth publishes a notebook per popular model. Its first cells are the most reliable source of current settings.

Check yourself

The decoded check line prints the system prompt and question as well as the answer. What is wrong?

  1. The response masking markers do not match your template
  2. The learning rate
  3. The GPU

If the markers are wrong, nothing gets masked and the model trains on the prompts too.

You run out of memory at step 1. First change to try?

  1. Raise the learning rate
  2. Raise the rank to 64
  3. Batch size 1 with more accumulation, and a shorter max length

Activations dominate memory, and they scale with batch and sequence length.

What three things does the script save?

  1. Only the dataset
  2. The adapter, the tokenizer files, and a Q4_K_M GGUF
  3. Nothing, it stays in memory

Keep the adapter and tokenizer files. The GGUF is ready for LM Studio or Ollama.
