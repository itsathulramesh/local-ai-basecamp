The most common reason a fine-tune "works in the notebook but is broken in LM Studio" is the chat template. This lesson explains the hidden text format every chat model expects, so your training data and your inference match exactly.

What you will learn

  • Distinguish base, instruct and thinking models and how each is made
  • Read a rendered chat template with its special tokens
  • Know where the template lives and what breaks when it is wrong
  • Decode model names and read a model card for training-relevant facts

Many recent models are hybrid: one model with a switch (often called enable_thinking) that turns thinking on or off through the chat template.

What a chat template is

The model does not see "messages". It sees one long string. The chat template is a small program (written in a language called Jinja) that turns a list of messages into that string with special marker tokens. For Qwen-family models a two-turn chat renders roughly like this:

<|im_start|>system
You are a concise tutor.<|im_end|>
<|im_start|>user
What is VRAM?<|im_end|>
<|im_start|>assistant
<think>

</think>

VRAM is the graphics card's own memory.<|im_end|>
  • <|im_start|> and <|im_end|> are special tokens: single token ids that mark the start and end of each turn.
  • The role (system, user, assistant, and sometimes tool) follows the start marker.
  • The empty <think></think> block is how this family represents "thinking turned off".
  • Generation stops when the model produces the end-of-turn token. That is the end-of-sequence (EOS) behaviour.

Other families use different markers (Llama, Gemma and Mistral each have their own). You never type these by hand. The tokenizer does it with apply_chat_template.

See it yourself

from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B")
msgs = [{"role": "system", "content": "You are a concise tutor."},
        {"role": "user", "content": "What is VRAM?"}]
print(tok.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True))

add_generation_prompt=True appends the opening of the assistant turn so the model knows it is its turn to speak. For training data you set it to False because the assistant answer is already included.

Where the template lives

  • In a Hugging Face model folder: inside tokenizer_config.json or a separate chat_template.jinja.
  • In a GGUF: copied into the file's metadata (tokenizer.chat_template) at conversion time.
  • In LM Studio: read from the GGUF, and overridable per model under My Models, then the settings for Prompt Template.
  • In Ollama: the TEMPLATE in the Modelfile, usually filled in automatically from the GGUF.

Concept: train and serve with the same template

Your training script renders examples with the model's own template. LM Studio or Ollama must render conversations with the same template, the same system prompt style and the same thinking setting. Lesson 9.6 shows how to check the template inside your exported GGUF.

Decoding model names

A name like Qwen3.5-9B-Instruct-abliterated-Q4_K_M.gguf breaks down into family and version (Qwen3.5), size (9B), kind (Instruct), modification (abliterated), quantization (Q4_K_M) and format (gguf). Other tags you will see: -it (instruct), -Base, -A3B (active parameters in a mixture-of-experts model), -VL (vision-language), -Coder.

Read a model card like a trainer

Before fine-tuning a model, find these on its card: the licence, whether it is base or instruct, its maximum context, its recommended sampling settings, whether it has a thinking switch, and whether official safetensors weights exist. You can only train from safetensors, never from a GGUF.

Check yourself

Your fine-tune prints <|im_end|> and keeps going. What is wrong?

  1. The learning rate was too high
  2. The chat template or end-of-sequence token does not match at inference
  3. The model is too small

The runtime is not treating the end-of-turn marker as the stop token.

Which file can you fine-tune from?

  1. A Q4_K_M GGUF
  2. An Ollama blob
  3. The original safetensors weights

Training libraries need the full-precision Hugging Face weights. GGUF is an inference format.

What does add_generation_prompt=True do?

  1. Adds the opening of the assistant turn so the model starts replying
  2. Generates training data
  3. Turns thinking on

It appends the assistant header. For training examples that already include the answer, set it to False.
