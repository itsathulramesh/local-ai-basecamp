LM Studio is the friendliest way to start: a desktop app with a model browser, a chat window and a local server. By the end of this lesson you will have a model answering questions on your own GPU.

What you will learn

  • Install LM Studio and download a model
  • Load it with the GPU and chat
  • Check that the GPU is really being used
  • Compare real VRAM use with your calculator estimate

1. Install

Download the Windows installer from lmstudio.ai and run it. It needs a 64-bit PC with a CPU that supports AVX2 (almost every processor from the last decade does). A GPU is optional but makes it much faster. Or from a terminal:

winget install ElementLabs.LMStudio

If the winget name does not work, use the installer. On first launch you may be offered a "developer" or "power user" view. Choose that, because it shows the settings this course explains.

2. Find and download a model

On your PC
  1. Click the Discover tab (magnifying glass).
  2. Search for a model in the size class from lesson 2.4, for example "qwen 9b" or "gemma 12b".
  3. LM Studio marks each file with a badge showing whether it will fully fit your GPU. Choose a Q4_K_M file for your first model.
  4. Click Download. It saves into the My Models folder.

Pick an instruct version, not a base model.

3. Load and chat

  1. Open the Chat tab and click the model selector at the top.
  2. Before loading, click the gear or "Load settings" for the model. Set GPU Offload to the maximum so all layers go to the GPU. Set Context Length to 8192 for now.
  3. Click Load, then type a message.

Try these three to see how the model behaves:

Explain what a token is to a ten-year-old in three sentences.
Write a Python function that returns the nth Fibonacci number.
What happened in the news yesterday?

The third one will fail or invent something. That is your first real lesson about knowledge cutoffs.

4. Check the GPU is being used

Open a second terminal and run nvidia-smi -l 1 while the model answers. You should see Memory-Usage jump by roughly the model's size plus the context cache, and GPU-Util rise while it generates. LM Studio also shows tokens per second under each reply.

Lab: verify the maths
  1. Note VRAM used before loading, after loading, and after a long reply.
  2. Compare with your lesson 3.3 calculator prediction. The weights part should be within a few percent. Overhead varies by about a gigabyte.
  3. Record tokens per second. Repeat once with 32K context and see how VRAM changes.

Useful tour

  • Chat: conversations, system prompt box, presets.
  • Discover: find and download models. You can also search Hugging Face directly.
  • My Models: the folder of downloaded files. Delete from here to free disk space.
  • Developer: the local server (lesson 6.2) and logs. Logs are the first place to look when something is wrong.
  • Settings: choose the runtime. The CUDA runtime is the one that uses your NVIDIA GPU, and LM Studio tells you when updates are available.
Guardrails

LM Studio can refuse to load a model that it thinks will not fit. That protects your system from freezing. You can relax it in settings, but a model that truly cannot fit will make Windows crawl.

Check yourself

How do you confirm the GPU is doing the work?

  1. Check the CPU temperature only
  2. Count the words in the reply
  3. Watch Memory-Usage and GPU-Util in nvidia-smi while it generates

VRAM use and GPU utilisation rising together show the model is on the GPU.

Which setting do you raise to put all model layers in VRAM?

  1. GPU Offload
  2. Temperature
  3. Top-p

GPU Offload sets how many layers go to the GPU.
