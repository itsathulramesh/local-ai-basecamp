You can build a "custom model" in five minutes with no training at all: a base model plus your system prompt, settings, and optionally a LoRA adapter, packaged under its own name. This is also how you will ship your fine-tunes later.

What you will learn

  • Write an Ollama Modelfile with every useful instruction
  • Import any GGUF from Hugging Face or your own training into Ollama
  • Attach a LoRA adapter without merging
  • Do the equivalent in LM Studio with presets and imports

Example 1: a persona on a library model

FROM llama3.2
SYSTEM """You are Basecamp Tutor. Explain AI concepts in plain English,
use one short example, and end with a one-line summary."""
PARAMETER temperature 0.5
PARAMETER num_ctx 8192
PARAMETER repeat_penalty 1.08
MESSAGE user What is a token?
MESSAGE assistant A token is a small chunk of text, about three quarters of a word. "Unbelievable" might be three tokens. Summary: models read and write tokens, not letters.
ollama create tutor -f Modelfile
ollama run tutor
ollama show tutor --modelfile   # print what Ollama stored

Example 2: import any GGUF

Download a GGUF from Hugging Face (lesson 4.4), put it next to a Modelfile, and point FROM at it:

FROM ./Some-Model-9B-Q4_K_M.gguf
PARAMETER num_ctx 8192

Ollama reads the chat template from the GGUF metadata. If replies look wrong (lesson 7.3), copy the TEMPLATE block from a known-good model of the same family with ollama show FAMILY --modelfile.

Shortcut

Ollama can also pull GGUF files directly from Hugging Face: ollama run hf.co/USER/REPO:Q4_K_M.

Example 3: base model plus your LoRA adapter

After module 9 you will have an adapter. Instead of merging it, you can attach it:

FROM ./Qwen3.5-2B-Q8_0.gguf
ADAPTER ./my-lora-F16.gguf
SYSTEM You are my house-style editor.
The base must match

An adapter only works on the exact base model it was trained on (same family, size and version). Applying it to a different model gives garbage or nothing. Keep a note of the base for every adapter you make.

The same in LM Studio

  • Presets save a system prompt plus sampling and load settings. Make one per job and switch in the chat sidebar.
  • Importing your own GGUF: lms import .\my-model-Q4_K_M.gguf --copy --user-repo you/my-model. It appears under My Models.
  • Prompt Template override per model, under My Models settings, if the auto-detected template is wrong.
  • At the time of writing, LM Studio's documentation does not describe loading a separate LoRA file onto a model, so for LM Studio you merge the adapter first (lesson 9.6).
