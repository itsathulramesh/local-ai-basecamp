On a model download page you will see several file types. Picking the wrong one is a common beginner stumble, and some formats carry a real security risk.

What you will learn

  • Tell GGUF, safetensors and pickle-based files apart
  • Know which format your tools expect
  • Understand why safetensors and GGUF are safer than older formats
  • Read a model's file list on Hugging Face

The main formats

FormatWhat it isUsed by
GGUF (.gguf)One self-contained file with weights, tokenizer and settings, designed for quantized local inferenceLM Studio, Ollama, llama.cpp
safetensors (.safetensors)A safe, fast file of raw tensors, often split into several shards, plus separate config and tokenizer filesHugging Face Transformers, PyTorch, fine-tuning tools, vLLM
PyTorch checkpoints (.bin, .pt, .pth)Python "pickle" files. Older, and can execute code when loaded.Legacy models
AWQ / GPTQ / EXL2Other quantization styles for GPU-only serversvLLM, ExLlama and similar
Concept: pick by purpose

To run a model in LM Studio or Ollama, download a GGUF. To train or modify a model, you want the original safetensors version. You will use both in module 9. A GGUF is what you get at the end of fine-tuning, after converting.

Why safety differs

Pickle-based files (.bin, .pt) are Python objects. Loading them can run arbitrary code hidden inside. A downloaded checkpoint from an untrusted source is therefore like running an unknown program. Safetensors and GGUF are plain data formats designed so that loading does not execute code. That is a big reason the community moved to them.

Safe habits
  • Prefer GGUF and safetensors. Be suspicious of .bin, .pt and .pkl files from unknown publishers.
  • Download from the model's real publisher, or from well-known community uploaders with many downloads and an active discussion page.
  • Check that the model card names its base model and licence.
  • Never run an installer, script or "launcher" that comes bundled with a model. Weights are data and need nothing like that.

Reading a Hugging Face file list

A GGUF repository typically lists the same model in many sizes:

Qwen-example-9B-Q4_K_M.gguf     5.6 GB
Qwen-example-9B-Q6_K.gguf       7.4 GB
Qwen-example-9B-Q8_0.gguf       9.5 GB
mmproj-F16.gguf                 0.9 GB   (vision add-on, only for image input)

You pick one quantization file, not all of them. If you see an mmproj file, that is the part that lets a vision-capable model look at images. Tools like LM Studio fetch it automatically if needed.

Two more things you will see

  • Sharded files such as model-00001-of-00004.safetensors are one model split into parts. Download all parts. Tools do it for you.
  • Base vs instruct in the name. "-Instruct" or "-it" models follow instructions. Base models only continue text. For chatting, always pick the instruct or chat version.

Check yourself

Which file do you download to chat with a model in LM Studio?

  1. A GGUF file
  2. A .pt checkpoint
  3. A zip of Python scripts

LM Studio runs GGUF models via llama.cpp.

Why is a .bin pickle checkpoint from a stranger risky?

  1. It is always corrupted
  2. It is too large
  3. Loading it can execute hidden code

Pickle can run arbitrary code. Safetensors and GGUF cannot do that by design.
