Training tools are developed on Linux first. On Windows you have three good options. This lesson sets up the one most tutorials assume (WSL2 with your NVIDIA GPU), shows the cloud alternative, and proves everything works before you spend time on a real run.

What you will learn

  • Choose between WSL2, native Windows and a cloud GPU
  • Set up WSL2 with GPU access, Python and Unsloth
  • Verify PyTorch sees your GPU
  • Rent a cloud GPU safely when your card is too small

WSL2 with your NVIDIA GPU

  1. Update your Windows NVIDIA driver (lesson 2.2). That driver also serves WSL2.
  2. In PowerShell: wsl --install (installs Ubuntu), then restart.
  3. Open Ubuntu from the Start menu, create a user, then check the GPU:
nvidia-smi        # should show your card, from inside Linux
Do not install a Linux NVIDIA driver inside WSL

The Windows driver provides GPU access to WSL2. Installing a Linux display driver inside Ubuntu breaks it. PyTorch and Unsloth bring the CUDA libraries they need.

Python and Unsloth inside WSL2

sudo apt update && sudo apt install -y python3-venv python3-pip git build-essential
mkdir -p ~/ai-lab/finetune && cd ~/ai-lab/finetune
python3 -m venv .venv && source .venv/bin/activate
pip install --upgrade pip
pip install --upgrade unsloth unsloth_zoo
python -c "import torch, unsloth, transformers, trl; print(torch.__version__, torch.cuda.is_available(), transformers.__version__)"

If the last line prints True, you are ready. Unsloth's installation steps change with CUDA and PyTorch versions, and newer model families need recent Transformers versions (Qwen3.5 needs Transformers 5). If anything fails, copy the install cell from Unsloth's current notebook for your model.

RTX 50-series cards

Blackwell GPUs need PyTorch built with CUDA 12.8 or newer. If you see "no kernel image is available", install the newest PyTorch build from pytorch.org first, then Unsloth.

Move your dataset in

Your Windows files are visible in WSL under /mnt/c. Copy the data into the Linux side for speed:

cp -r /mnt/c/Users/$USER_WINDOWS/ai-lab/finetune/data ~/ai-lab/finetune/
# replace $USER_WINDOWS with your Windows user name
ls ~/ai-lab/finetune/data

Windows Explorer can open the Linux side too: type \\wsl$ in the address bar.

Prove the GPU works for training

import torch
p = torch.cuda.get_device_properties(0)
print(p.name, round(p.total_memory / 1024**3, 1), "GiB")
x = torch.randn(4096, 4096, device="cuda", requires_grad=True)
loss = (x @ x).mean()
loss.backward()
print("forward + backward on GPU OK; peak memory",
      round(torch.cuda.max_memory_allocated() / 1024**3, 2), "GiB")

Cloud safety checklist
  • Upload only scrubbed data you would be comfortable seeing leak. On marketplaces, the host has physical access to the machine.
  • Log in with an SSH key, not a password. Keep Jupyter or any web UI bound to 127.0.0.1 and reach it through an SSH tunnel: ssh -L 8888:127.0.0.1:8888 user@host.
  • No access tokens on the machine unless needed. If you must push to Hugging Face, use a fine-grained token for one private repo and revoke it afterwards.
  • Check copied notebooks for push_to_hub calls before running them.
  • After downloading results, verify checksums, then delete the instance and its storage volume.

Check yourself

Inside WSL2, nvidia-smi fails. What should you NOT do?

  1. Update the Windows NVIDIA driver
  2. Install a Linux NVIDIA display driver inside Ubuntu
  3. Restart WSL with wsl --shutdown

The Windows driver provides GPU access. A Linux driver inside WSL breaks it.

Where should you keep training files when using WSL2?

  1. On a USB stick
  2. Under /mnt/c
  3. In the Linux home folder

Crossing the Windows-Linux boundary is much slower.
